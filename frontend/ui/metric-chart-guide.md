# CPU / 메모리 일별 사용률 차트 구현 가이드

이 문서는 메트릭 차트 화면을 구현하는 에이전트를 위한 명세다.
시각 기준은 같은 폴더의 `metric-chart-mockup.html`이다. 구현 전에 이 파일을 브라우저에서 열어 결과물과 맞춰 볼 것.
목업은 Chart.js로 그렸지만 **구현은 사내 echarts 기반 라이브러리**로 한다. 사용법은 echarts와 동일하다.
import 방식과 초기화 패턴은 이 프로젝트에 이미 있는 차트 코드를 따른다.

## 1. 화면 구성

위에서 아래로 다음 순서다.

1. 요약 카드 2개 (CPU, 메모리). 2열 그리드, 간격 10px.
2. 범례 한 줄.
3. 라인 차트 1개. CPU와 메모리, 평균과 최대, 총 4개의 선을 같은 y축에 그린다.

## 2. 데이터 명세

백엔드는 **일자별 지수**를 준다. 최근 30일, 하루에 한 건이다.

| 필드 | 의미 | 단위 |
|---|---|---|
| `date` | 일자 (`YYYY-MM-DD`) | - |
| `cpuLimit` | CPU 한도 | core (예: 0.5) |
| `cpuAvg` | CPU 사용률 평균 | 한도 대비 % (0~100) |
| `cpuMax` | CPU 사용률 최대 | 한도 대비 % (0~100) |
| `memLimit` | 메모리 한도 | GiB (예: 5) |
| `memAvg` | 메모리 사용률 평균 | 한도 대비 % (0~100) |
| `memMax` | 메모리 사용률 최대 | 한도 대비 % (0~100) |

필드명은 예시다. 실제 API 응답의 필드명에 맞춰 매핑하고, 위 의미만 유지한다.
한도는 날짜마다 값이 다를 수 있으므로 **항상 그 일자의 한도**를 쓴다. 마지막 값이나 첫 값을 고정해서 쓰지 않는다.

## 3. 핵심 설계 결정 (바꾸지 말 것)

- **y축은 하나, 0~100%로 고정**한다. `min: 0`, `max: 100`, 눈금은 25 간격이다. 이중 y축은 쓰지 않는다.
- **한도는 차트에 선으로 그리지 않는다.** 한도는 절대값(core, GiB)이라 % 축에 올릴 수 없다. 한도를 시리즈로 추가하지 않는다. 한도는 요약 카드 상단 텍스트(`한도 0.5 core`)와 툴팁의 절대값 계산에만 쓴다. 차트의 100% 선이 곧 한도다.
- **CPU와 메모리를 한 차트에 합친다.** 둘 다 %라서 같은 축에서 비교할 수 있다.
- **막대 차트는 쓰지 않는다.** 30일 추이이므로 라인 차트다.

## 4. 라인 차트 상세

x축은 category 타입이고 라벨은 `MM/DD`다. 라벨은 최대 6개 정도만 보이게 간격을 자동으로 줄인다.
눈금 라벨은 회전하지 않는다.

| 시리즈 | 이름 | 색 | 선 굵기 | 선 모양 |
|---|---|---|---|---|
| 1 | CPU 최대 | cpu-max | 1.2 | 실선 |
| 2 | CPU 평균 | cpu-avg | 2.5 | 실선 |
| 3 | 메모리 최대 | mem-max | 1.2 | 점선 `[3, 3]` |
| 4 | 메모리 평균 | mem-avg | 2.5 | 파선 `[6, 3]` |

- 평균이 주인공이다. 최대는 스파이크 확인용이라 얇고 연하게 그린다.
- CPU는 실선, 메모리는 점선 계열로 구분한다. **색만으로 구분하지 않는다.** 색을 구분하지 못해도 읽혀야 한다.
- 선은 부드럽게 한다 (`smooth: 0.25` 정도). 평소에는 마커를 숨긴다.
- **경고 점**: 최대값이 85%를 초과한 일자만 빨간 점(`bad` 색, 지름 약 8px)을 그린다. 그 외 점은 숨긴다. 85는 상수(`WARN = 85`)로 둔다.
- 평균 선 아래에 면 채우기는 하지 않는다. 선이 4개라 겹쳐 지저분해진다.
- y축 눈금 라벨은 `25%` 형식이다. 세로 격자선은 없고 가로 격자선만 옅게 둔다. y축 선은 그리지 않는다.
- 차트 높이는 260px 정도다. 폭은 부모에 맞춘다.

### 툴팁

x축 기준(`trigger: 'axis'`)이다. 제목은 전체 일자(`YYYY-MM-DD`)다. 각 줄은 다음 형식이다.

```
CPU 평균: 38% (0.19 core)
메모리 최대: 87% (4.35 GiB)
```

절대값은 `한도 × % / 100`이고 소수 둘째 자리까지 표시한다. 한도는 **해당 일자의 한도**다.
`formatter` 안에서 `dataIndex`로 원본 데이터를 찾아 계산한다.

### 범례

목업처럼 직접 만든 HTML 범례를 쓴다. 각 항목에 **실제 선의 굵기와 모양**이 같이 보여야 한다.
echarts 기본 범례로 대체해도 되지만, 그 경우 평균과 최대, CPU와 메모리의 선 모양 차이가 범례에서 구분되어야 한다.
빨간 점 항목(`85% 초과`)도 함께 둔다.

## 5. 요약 카드

카드는 CPU와 메모리 각각 하나이고, **가장 최근 일자**(배열의 마지막) 값을 쓴다.

- 상단 줄: 왼쪽에 `CPU · MM/DD`, 오른쪽에 `한도 0.5 core`.
- 큰 숫자: 평균 사용률 `38%`(24px, 굵기 500) 옆에 작은 글씨로 `평균`.
- 미터: 높이 8px, 둥근 트랙. 채운 막대의 너비가 평균%이고, **세로 눈금(너비 2px, 높이 14px)이 최대% 위치**다.
- 하단 줄: 왼쪽에 평균의 절대값(`0.19 core`), 오른쪽에 `최대 71%`.
- 최대가 85%를 넘으면 눈금 색과 오른쪽 텍스트가 빨강으로 바뀌고 텍스트 끝에 ` · 경고`가 붙는다.
- 카드 배경은 `tile` 색, 모서리 8px, 안쪽 여백 12px이다. 테두리와 그림자는 없다.

## 6. 색상 팔레트

| 용도 | 라이트 | 다크 |
|---|---|---|
| CPU 평균 | `#2a78d6` | `#3987e5` |
| CPU 최대 | `#7fb1ea` | `#7fb1ea` |
| 메모리 평균 | `#6250d6` | `#9085e9` |
| 메모리 최대 | `#a99fe8` | `#a99fe8` |
| 경고 | `#d03b3b` | `#d03b3b` |
| 차트 가로 격자선 | `#e1e0d9` | `#2c2c2a` |
| 축 눈금 라벨 | `#898781` | `#898781` |
| 요약 카드 배경 | `#f1f0ec` | `#262624` |
| 미터 트랙 | `#e1e0d9` | `#2c2c2a` |

- 색은 **항목에 고정**한다. CPU는 항상 파랑, 메모리는 항상 보라다. 값의 순위나 필터에 따라 색이 바뀌지 않는다.
- 빨강(`경고`)은 85% 초과에만 쓴다. 다른 용도로 쓰면 의미가 흐려진다.
- 다크 모드를 지원한다. 라이트/다크 값은 프로젝트의 기존 테마 방식에 맞춰 토큰으로 분리한다.

## 7. echarts option 뼈대

참고용 구조이고, 그대로 복사하지 않는다. 프로젝트의 차트 컴포넌트 규약에 맞춘다.

```ts
const WARN = 85;

const makeSeries = (name, values, color, width, dash) => ({
  name,
  type: 'line',
  smooth: 0.25,
  showSymbol: false,
  lineStyle: { color, width, type: dash },       // 'solid' | [6, 3] | [3, 3]
  itemStyle: { color },
  data: values.map(v => ({
    value: v,
    // 최대 시리즈만: 85% 초과 일자에 빨간 점
    ...(isMax && v > WARN
      ? { symbol: 'circle', symbolSize: 8, showSymbol: true, itemStyle: { color: BAD } }
      : {}),
  })),
});

const option = {
  grid: { left: 40, right: 12, top: 12, bottom: 28 },
  tooltip: {
    trigger: 'axis',
    formatter: params => {
      const i = params[0].dataIndex;
      const row = data[i];                         // 그 일자의 원본 행
      // 제목: row.date, 각 줄: `${name}: ${v}% (${(limit * v / 100).toFixed(2)} ${unit})`
      // CPU 계열은 row.cpuLimit / core, 메모리 계열은 row.memLimit / GiB
    },
  },
  xAxis: {
    type: 'category',
    data: data.map(d => d.date.slice(5).replace('-', '/')),
    boundaryGap: false,
    axisLabel: { color: '#898781', rotate: 0, hideOverlap: true },
    axisTick: { show: false },
  },
  yAxis: {
    type: 'value', min: 0, max: 100, interval: 25,
    axisLabel: { color: '#898781', formatter: '{value}%' },
    axisLine: { show: false },
    splitLine: { lineStyle: { color: GRID } },
  },
  series: [ /* CPU 최대, CPU 평균, 메모리 최대, 메모리 평균 순서 */ ],
};
```

## 8. 엣지 케이스

- **데이터가 비어 있음**: 차트 영역에 `표시할 데이터가 없어요`를 중앙 정렬로 보여준다. 카드는 숨기거나 `-`로 채운다.
- **일부 일자가 누락됨(null)**: 선을 이어 붙이지 않는다 (`connectNulls: false`). 누락된 날은 선이 끊긴다. 툴팁에는 `-`로 표시한다.
- **한도가 중간에 바뀜**: 같은 사용량도 한도가 바뀌면 %가 급변한다. 툴팁의 절대값은 날짜별 한도로 계산하므로 문제없다. 한도가 바뀐 날에 세로 보조선을 표시하는 건 **선택 사항**이다.
- **한도가 0이거나 없음**: 해당 일자의 절대값은 `-`로 표시한다. 0으로 나누지 않는다.
- **값이 100을 넘음**: 서버 값이 100을 넘으면 y축 최대는 100으로 두고 선이 위쪽에서 잘리게 둔다. 이는 장애 상황의 신호이므로 숨기지 않는다. 필요하면 별도 논의한다.
- **로딩 중**: 차트 높이(260px)를 유지한 스켈레톤을 보여서 레이아웃이 튀지 않게 한다.
- **접근성**: 차트 컨테이너에 `role="img"`와 요약 `aria-label`을 둔다. 예: `최근 30일 CPU와 메모리 사용률 추이`.

## 9. 하지 말 것

- 이중 y축을 쓰지 않는다.
- 한도를 선이나 시리즈로 추가하지 않는다.
- 색만으로 시리즈를 구분하지 않는다.
- 평균 선에 면 채우기를 넣지 않는다.
- 값의 크기나 순위에 따라 시리즈 색을 바꾸지 않는다.
- 팔레트에 없는 색을 임의로 추가하지 않는다.

## 10. 완료 기준

- 목업과 나란히 놓았을 때 레이아웃, 선 굵기와 모양, 색이 같다.
- 라이트와 다크 모드 모두 라벨과 선이 잘 읽힌다.
- 툴팁의 절대값이 일자별 한도로 계산된다.
- 최대 85% 초과 일자에만 빨간 점이 찍히고, 요약 카드의 경고 표시와 기준이 같다.
- 데이터 비어 있음, 누락, 로딩 상태가 처리된다.
